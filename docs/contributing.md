# Руководство для контрибьюторов Synapse Core v43

Мы рады любому вкладу в развитие Synapse Core v43! Это руководство поможет вам начать работу и внести свой вклад в проект.

## 1. Как внести вклад

1.  **Форкните репозиторий**: Начните с создания форка репозитория Synapse Core на GitHub.
2.  **Клонируйте репозиторий**: Клонируйте ваш форк на локальную машину:
    ```bash
    git clone https://github.com/YOUR_USERNAME/synapse-core.git
    cd synapse-core
    ```
3.  **Создайте виртуальное окружение**: Рекомендуется использовать виртуальное окружение для управления зависимостями:
    ```bash
    python3 -m venv venv
    source venv/bin/activate
    ```
4.  **Установите зависимости**: Установите зависимости для разработки и тестирования:
    ```bash
    pip install -e .[test]
    ```
5.  **Создайте новую ветку**: Создайте ветку для вашей новой функции или исправления ошибки:
    ```bash
    git checkout -b feature/your-feature-name
    ```
6.  **Внесите изменения**: Напишите код, тесты и обновите документацию.
7.  **Запустите тесты**: Убедитесь, что все существующие тесты проходят и ваши новые тесты также успешны:
    ```bash
    pytest
    ```
8.  **Отформатируйте код**: Используйте `black` и `isort` для автоматического форматирования кода:
    ```bash
    black .
    isort .
    ```
9.  **Зафиксируйте изменения**: Напишите понятное сообщение коммита:
    ```bash
    git commit -m "feat: Add new amazing feature"
    ```
10. **Отправьте изменения**: Отправьте вашу ветку в ваш форк:
    ```bash
    git push origin feature/your-feature-name
    ```
11. **Создайте Pull Request**: Откройте Pull Request из вашей ветки в основную ветку `main` оригинального репозитория. Подробно опишите ваши изменения.

## 2. Рекомендации по коду

*   **Соглашения по именованию**: Следуйте PEP 8.
*   **Типизация**: Используйте аннотации типов (`type hints`) для улучшения читаемости и поддержки кода.
*   **Асинхронность**: Используйте `asyncio` для всех операций ввода/вывода и длительных задач.
*   **Тесты**: Каждое изменение должно сопровождаться соответствующими тестами (юнит-тесты, интеграционные тесты).
*   **Документация**: Обновляйте документацию для любых новых функций или изменений в API.
*   **Логирование**: Используйте стандартный модуль `logging` для вывода информации и отладки.

## 3. Сообщения коммитов

Мы придерживаемся соглашения о сообщениях коммитов Conventional Commits. Это помогает генерировать CHANGELOG и лучше понимать историю проекта.

Примеры:

*   `feat: Добавлена новая функция X`
*   `fix: Исправлена ошибка Y`
*   `docs: Обновлена документация для Z`
*   `chore: Обновлены зависимости`

## 4. Лицензия

Внося свой вклад, вы соглашаетесь с тем, что ваш код будет распространяться под лицензией MIT.
